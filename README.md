# DVP Meeting Prep

An internal tool that assembles advisor context from Salesforce, Tableau, and
consultant scorecard data, and generates a downloadable Word document to prep
for DVP (District Vice President) advisor meetings using Gemini Enterprise.

It has two ways to work with it:

- **Web app** (recommended): search for an advisor, click a button, download
  a formatted `.docx` meeting prep document. Upload new Tableau exports or
  consultant scorecards through a browser page.
- **CLI scripts**: the original terminal-driven workflow, still available for
  bulk ingestion and scripted/automated use.

## How it works

```
Salesforce (live API, default) ─┐
   .xlsx export (fallback)      │
Tableau export (.csv)           ├─> parse & ingest ─> local SQLite ─> query by advisor ─> LLM prompt ─> Gemini Enterprise ─> Markdown ─> .docx
Consultant scorecard (.xlsx)    ┘
```

Advisor/Task data is pulled live from Salesforce by default
(`DATA_SOURCE=salesforce`) via `simple-salesforce` -- see
[docs/SALESFORCE_SETUP.md](docs/SALESFORCE_SETUP.md) for connecting it to a
sandbox or production org. A local `.xlsx` export remains available as a
fallback (`DATA_SOURCE=csv`) for offline development or when Salesforce
access isn't available; `data_source.py` is the only place that decision is
made, so nothing downstream needs to know which source produced the rows.
Consultant scorecards and Tableau exports are uploaded one at a time through
the web app's `/upload` page (there is no live API for those two).

All application data lives in a single local SQLite database file
(`data/dvp_meeting_prep.sqlite3` by default) -- no external database server,
account, or credentials to manage. Meeting prep text is generated by
**Gemini Enterprise** (via the `google-genai` SDK) using **Google
Application Default Credentials (ADC)** -- there is no API key anywhere in
this application.

Tableau and consultant scorecard uploads are dedup-safe: re-uploading the
same file (or one with overlapping rows) never creates duplicate rows. Rows
are matched by a content hash (Tableau, consultant scorecard raw rows) or by
natural key (consultant scorecard monthly/metric rows upsert on report date +
advisor number). Salesforce extraction instead fully replaces
`salesforce_data` on each run (matching the original CSV-based behavior), so
re-running it is also safe, just via a different mechanism.

## Project layout


## 1) Setup

**Prerequisites:** Python 3.12+, the [gcloud CLI](https://cloud.google.com/sdk/docs/install)
(for one-time ADC login only -- the app itself never shells out to `gcloud`),
and a Google Cloud project with the Vertex AI API enabled and Gemini
Enterprise access. No database server, account, or API key is required.

```powershell
# 1. Create/activate a virtual environment
python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1

# 2. Install dependencies (requirements-dev.txt adds pytest + playwright, for
#    tests/e2e_smoke_test.py -- not needed just to run the app)
python -m pip install -r requirements.txt
```

```powershell
# 3. Copy the env template and fill in real values
Copy-Item .env.example .env
```

Edit `.env`:

- `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`, `GOOGLE_GENAI_MODEL` --
  your Google Cloud project ID, region (e.g. `us-central1`), and the Gemini
  model name your project has access to. See "Google ADC setup" below for
  where these values come from and how to authenticate.
- `SQLITE_DB_PATH` -- defaults to `data/dvp_meeting_prep.sqlite3` (resolved
  relative to the project root, not your current directory); the default is
  fine for local development.

Salesforce is the default data source (`DATA_SOURCE=salesforce`) and needs
its own credentials/config — copy `.env.sandbox.example` to `.env.sandbox`
(loaded automatically when `APP_ENV=sandbox`, the default) and follow
**[docs/SALESFORCE_SETUP.md](docs/SALESFORCE_SETUP.md)**, which covers
authentication, running metadata discovery to find your org's real
object/field names, dry runs, and troubleshooting. Set `DATA_SOURCE=csv` to
use the local `.xlsx` fallback instead (no Salesforce credentials needed).

```powershell

#    the login only if ADC isn't already present, and verifies the result.
```

```powershell

```

```powershell

```

```powershell

```

```powershell
# 8. Run the tests (mocked -- no live Google/Salesforce calls, no real DB touched)
python -m pytest tests/
```

```powershell
# 9. Start the web app
python scripts/run_server.py
```

```powershell
# 10. Open the app
Start-Process http://127.0.0.1:8000
```

### Google ADC setup

This app authenticates to Gemini Enterprise using **Google Application
Default Credentials** -- never an API key, never a manually copied token, and
the application code never shells out to `gcloud` itself. For local
development, the wrapped/idempotent way (verifies `gcloud` is installed,
skips the login if ADC already exists, then verifies the app's own config):

```powershell
.\scripts\setup_google_auth.ps1                       # PowerShell (Windows)
.\scripts\setup_google_auth.ps1 -Project my-gcp-project-id
```

```bash
bash scripts/setup_google_auth.sh                      # WSL / Linux / macOS
bash scripts/setup_google_auth.sh --project my-gcp-project-id
```

Or run the underlying commands yourself:

```powershell
gcloud auth application-default login
```

This opens a browser, signs you in, and writes credentials to a well-known
location (`%APPDATA%\gcloud\application_default_credentials.json` on
Windows, `~/.config/gcloud/application_default_credentials.json` on
macOS/Linux) that `google.auth.default()` discovers automatically -- nothing
in this app's config points at that file directly. Confirm it worked and see
exactly what project/location/model the app will use, without making a paid
call:

```powershell
python scripts/check_google_auth.py
```

Add `--live --yes-i-want-to-call-gemini` only when you deliberately want to
confirm live connectivity (costs quota) -- see
[docs/TESTING_GEMINI_SQLITE_MIGRATION.md](docs/TESTING_GEMINI_SQLITE_MIGRATION.md)
for the full explanation and expected output of each mode.

**Production** must not use a developer's local ADC login. Instead, run the
app under a Google Cloud runtime identity (a GKE Workload Identity service
account, a Cloud Run service identity, etc.) that already has the Vertex AI
IAM role granted -- `google.auth.default()` picks that up automatically with
no code change and no credential file anywhere on disk.

## 2) SQLite database

All application data lives in one SQLite file
(`SQLITE_DB_PATH`, default `data/dvp_meeting_prep.sqlite3`, resolved
relative to the project root regardless of your current working directory).
No server process, account, or network connection is involved. The
`sqlite3` command-line program is **never required** -- only Python's
built-in `sqlite3` module is used by the application itself; installing the
CLI is purely optional, for manual inspection.

```powershell
# Create the schema (fresh DB) or apply any pending migrations (existing DB).
# Idempotent and safe to rerun any number of times -- never drops tables,
# deletes rows, or resets data.
python scripts/init_sqlite.py
```

```powershell
# Verify every expected table/index exists, foreign keys are enabled,
# migrations are recorded, and run a quick read/write/integrity check.
python scripts/check_sqlite_tables.py
```

Cross-platform idempotent setup scripts wrap both of the above (verify
Python, verify the `sqlite3` module, run init + check):

```powershell
.\scripts\setup_sqlite.ps1                # PowerShell (Windows)
.\scripts\setup_sqlite.ps1 -InstallCli    # also installs the sqlite3 CLI via winget, for manual inspection only
```

```bash
bash scripts/setup_sqlite.sh              # WSL / Linux / macOS
bash scripts/setup_sqlite.sh --install-cli
```

Neither script ever invokes `sudo` unless you explicitly ask for the CLI
install, and neither downloads an unverified executable -- the CLI install
goes through `winget`/`apt-get` only.

There is intentionally no destructive "reset" command anywhere in this
migration -- nothing in the app can drop tables or delete rows outside of
manually running SQL yourself against the `.sqlite3` file. See "Cleanup and
reset" in
[docs/TESTING_GEMINI_SQLITE_MIGRATION.md](docs/TESTING_GEMINI_SQLITE_MIGRATION.md)
if you need to start over.

## 3) Run the web app

```powershell
python scripts/run_server.py
```

Then open http://127.0.0.1:8000 in a browser.

- **Home page (`/`)** — start typing an advisor name; matching advisors
  (sourced from Salesforce + Tableau data already in the database) appear in
  a dropdown, shown in caps for readability. Click one, then click "Get
  meeting prep document" to generate and download a `.docx` file. The
  generated Markdown and prompt are also logged to the
  `meeting_prep_documents` table for audit purposes (disable with
  `STORE_LLM_AUDIT_CONTENT=false` -- it contains Salesforce notes).
- **Upload page (`/upload`)** — upload a consultant scorecard workbook or a
  Tableau CSV export. Each upload reports how many rows were parsed, how many
  were newly added, and how many were already present (skipped as
  duplicates). Salesforce is intentionally not uploadable here.

`--host` / `--port` flags are available if you need to bind elsewhere:
`python scripts/run_server.py --host 0.0.0.0 --port 8080`.

On startup, the app calls `ensure_schema_ready()` (creates any missing
tables/indexes and applies pending migrations -- never destructive) and
creates a single Gemini client for the process lifetime; both are torn down
cleanly on shutdown.

### API reference

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Liveness check -- also verifies the SQLite database is reachable |
| GET | `/api/advisors?q=<prefix>&limit=20` | Advisor name search |
| POST | `/api/uploads/tableau` | Upload a Tableau CSV (`multipart/form-data`, field `file`) |
| POST | `/api/uploads/consultant-scorecard` | Upload a scorecard `.xlsx` (`multipart/form-data`, field `file`) |
| POST | `/api/meeting-prep` | `{"advisor_name": "..."}` -> streams back a `.docx` |

## 4) Run with Docker

An alternative to the local venv setup above. The image runs the web app
only; SQLite persists to a mounted volume (`./data:/app/data` via
`docker-compose.yml`, or a named Docker volume) so data survives container
restarts and rebuilds, and Gemini Enterprise is reached over the network
using ADC. The image never bakes in a populated database or any credentials.

```powershell
docker compose up --build
```

Then open http://127.0.0.1:8000, same as running locally. `docker-compose.yml`
reads `.env` via `env_file` and mounts a named volume at `/app/data`, so
nothing needs to be baked into the image or passed on the command line. Stop
it with `docker compose down` (the volume, and your data, persist across
this -- use `docker compose down -v` if you deliberately want to discard it).

Without Compose:

```powershell
docker build -t dvp-meeting-prep .
docker run --rm -p 8000:8000 --env-file .env -v dvp_sqlite_data:/app/data dvp-meeting-prep
```

Notes:
- The image installs only `requirements.txt` (runtime deps) — Playwright and
  its browser binaries are never pulled into it.
- Runs as a non-root user (`appuser`), which owns `/app/data` so a fresh
  named volume mounted there inherits correct write permissions on first
  use. `HEALTHCHECK` hits `/api/health`, which now also verifies SQLite
  readiness (`docker ps` / `docker inspect` will show `healthy`/`unhealthy`).
- The FastAPI lifespan handler calls `ensure_schema_ready()` before the app
  starts accepting requests, so the schema is created/migrated safely on
  every container boot -- no separate init step is needed in the image.
- One-off scripts (e.g. re-running ingestion) can be run in the same image:
  `docker compose run --rm web python scripts/ingest_all.py`.
- The `.env` file is never copied into the image (see `.dockerignore`) — it's
  only ever injected at container start, so rebuilding the image doesn't
  require secrets and the image itself doesn't contain them.
- `docker-compose.yml` only loads the single `.env` file (Compose's
  `env_file:` doesn't support the `APP_ENV`-based `.env.sandbox` /
  `.env.production` convention config.py otherwise resolves) — put every
  variable you need, including the `SF_*` ones from
  [docs/SALESFORCE_SETUP.md](docs/SALESFORCE_SETUP.md), directly in `.env`
  when running via Docker, rather than splitting them into `.env.sandbox`.
- **Local ADC in Docker is dev-only.** `docker-compose.yml` has a commented-out
  volume mount for `~/.config/gcloud` so a container can use your host's ADC
  login during local development. Never do this in production -- production
  must run under a Google Cloud runtime identity (GKE/Cloud Run service
  account) instead, so no credential file needs to exist on disk in the
  container at all.

## 5) CLI scripts

Still useful for bulk-loading sample data or scripted runs without the UI.

```powershell
# Bulk-ingest all three sources into SQLite (Salesforce portion uses DATA_SOURCE; replaces existing rows by default)
python scripts/ingest_all.py

# Salesforce-specific: discovery, dry run, full extraction (see docs/SALESFORCE_SETUP.md)
python scripts/salesforce_extract.py --discover-salesforce
python scripts/salesforce_extract.py --dry-run
python scripts/salesforce_extract.py

# Verify the SQLite schema is ready (tables, indexes, migrations, foreign keys)
python scripts/check_sqlite_tables.py

# Verify Google ADC + Gemini configuration (no paid call by default)
python scripts/check_google_auth.py

# Quick advisor query (prints raw rows from every source table)
python scripts/query_advisor.py "Avery Benton"

# Interactive flow: pick an advisor, preview the prompt, optionally generate
python scripts/interactive_meeting_prep.py --query-output output/query_results_avery.txt --prompt-output output/prompt_preview_avery.txt

# Direct generation, saved straight to a Markdown file
python scripts/run_meeting_prep.py "Avery Benton" --save output/avery_benton_meeting_prep.md
```

Note: the CLI scripts save Markdown, not `.docx` — Word export is currently
only available through the web app's `/api/meeting-prep` endpoint. Each
script that calls Gemini creates and closes its own client for that single
invocation (rather than sharing the web app's process-lifetime client).

## 6) Testing

```powershell
python -m pytest tests/          # mocked unit tests -- no network calls, no real DB touched, safe to run anytime
```

Every test that needs a database uses a throwaway SQLite file under
pytest's `tmp_path` (see the `sqlite_db` fixture in `tests/conftest.py`) --
never your real `data/dvp_meeting_prep.sqlite3`. Every test that needs
Gemini mocks the `google-genai` client (see `tests/test_gemini_llm.py`) --
no ADC, network access, or Google Cloud project is required to run the
suite. The Salesforce integration (auth, SOQL building/escaping, field
selection, row normalization, count/integrity validation, the `DATA_SOURCE`
factory) is similarly fully mocked (`simple-salesforce` is never actually
called).

- `python -m pyflakes src/dvp_meeting_prep scripts tests` — static check for
  unused imports/variables.
- `tests/e2e_smoke_test.py` — a Playwright browser test that drives the real
  UI end to end (search -> select -> generate -> download -> verify the
  `.docx`; upload a Tableau CSV and a scorecard; verify empty-search state;
  fail on any JS console error). It writes to your real local SQLite

## Data model

See `sql/schema.sql` for the full DDL (the original Postgres/Supabase
schema is archived, unused, in `sql/postgres_schema_legacy.sql` for
historical reference). Summary:

| Table | Written by | Read by |
| --- | --- | --- |
| `salesforce_data` | `scripts/ingest_all.py`, `scripts/salesforce_extract.py` (live Salesforce or `.xlsx` fallback, per `DATA_SOURCE`) | advisor search, meeting prep |
| `tableau_data` | `scripts/ingest_all.py`, `/api/uploads/tableau` | advisor search, meeting prep |
| `consultant_scorecard_raw` | `scripts/ingest_all.py`, `/api/uploads/consultant-scorecard` | audit trail only |
| `consultant_scorecard_monthly` | same as above | meeting prep |
| `consultant_scorecard_metric` | same as above | meeting prep |
| `consultant_scorecard_data` | `scripts/ingest_all.py` | legacy flat mirror of the scorecard, kept for the sample health-check script; not read by the meeting prep flow |
| `upload_batches` | `/api/uploads/*` | audit trail of uploads made through the UI |
| `meeting_prep_documents` | `/api/meeting-prep` | audit trail of generated documents (only when `STORE_LLM_AUDIT_CONTENT=true`) |
| `schema_migrations` | `db.py`'s migration runner | tracks which migrations have been applied (version, name, applied_at) |

Advisor identity note: Salesforce/Tableau store names as `"First Last"`;
consultant scorecard rows store `"LAST, FIRST"` in caps. `query.py` bridges
this by trying both forms (and, failing that, an advisor number bridged from
the other source tables) when looking up a consultant scorecard row, so the
web UI only needs to show/search the Salesforce/Tableau form.

## Troubleshooting

| Symptom | Likely cause / fix |
| --- | --- |
| `GeminiAuthError` / "Application Default Credentials were not found" | Run `gcloud auth application-default login`, then `python scripts/check_google_auth.py` to confirm. |
| `GeminiPermissionError` (HTTP 403) | The Vertex AI API isn't enabled on the project, or the authenticated identity lacks the required IAM role. |
| `GeminiConfigError` (HTTP 404) | Check `GOOGLE_GENAI_MODEL` / `GOOGLE_CLOUD_PROJECT` / `GOOGLE_CLOUD_LOCATION` -- the model or resource wasn't found with that combination. |
| `GeminiQuotaError` | Rate limited or quota exhausted; the app already retries transient 429/5xx errors with backoff before raising this. |
| `SchemaNotReadyError` | Run `python scripts/init_sqlite.py`, then `python scripts/check_sqlite_tables.py` to confirm. |
| `DatabaseLockedError` | Another process is writing to the same `.sqlite3` file past `SQLITE_BUSY_TIMEOUT_MS`; only one writer at a time is supported by design. |
| `DatabaseNotWritableError` | The path in `SQLITE_DB_PATH` (or its parent directory) isn't writable by the current user/container. |

See
[docs/TESTING_GEMINI_SQLITE_MIGRATION.md](docs/TESTING_GEMINI_SQLITE_MIGRATION.md)
for the full list of expected failure scenarios and exact error messages.
